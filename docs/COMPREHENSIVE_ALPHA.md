# Comprehensive alpha

## Why breadth comes first

Invariant already contains deep, receipt-bound work in several mathematical and physical lanes.
The next product milestone is different: demonstrate that the *whole discovery loop* works across
the supported mechanisms before spending more time exhausting any one theorem family or tensor
domain.

The comprehensive alpha is therefore a systems milestone, not a claim that the mathematics,
physics, or observational program is complete. A subsystem counts as exercised only when its
output crosses the same typed, hash-bound, fail-closed boundaries used by the rest of the product.

## Three distinct completion labels

Every alpha result uses one of these labels:

| Label | Meaning |
| --- | --- |
| Implemented | The bounded API, schemas, validators, and negative controls exist. |
| Exercised end to end | A real candidate or packet traversed the subsystem and produced replayable receipts. |
| Scientifically validated | The relevant proof kernel or authorized evidence gate accepted the claim within its declared scope. |

`Implemented` never implies `exercised end to end`, and neither label implies `scientifically
validated`. Missing evidence remains a block. A generator, heuristic score, Pareto rank, LLM
proposal, GPU computation, or corpus miss can never promote itself.

## Alpha vertical slices

### 1. Candidate generation

Run at least one bounded candidate through each registered generator family:

- grammar;
- symbolic templates;
- evolutionary mutation/crossover;
- Bayesian prioritization;
- e-graph saturation;
- cross-domain structural transfer;
- quarantined LLM proposal generation.

Each output must be a Sigma Core `CandidateArtifact` with exact provenance, deterministic replay,
bounded work accounting, and explicit `truth=false` and `promotion=false` boundaries.

### 2. Common evaluation and explanation

Feed the generator outputs into one common domain pack and exercise all terminal states:

- one candidate passes every declared hard gate;
- one candidate is rejected by a counterexample or violated premise;
- one candidate is blocked by missing evidence;
- one injected evaluator failure becomes an error receipt.

Only the all-pass candidate may receive soft metrics or a Pareto front. The resulting explanation
must bind the contributing gate receipts, checks, evidence, and metric receipts. Replay must recover
the same result byte for byte.

### 3. External proof kernel

Send one bounded theorem through the Lean adapter with an allowed-premise manifest and dependency
audit. If a compatible Lean executable is unavailable, the alpha records an exact readiness block;
it does not substitute a mocked kernel pass. A successful kernel receipt is scoped to the theorem,
source bytes, executable bytes, output bytes, and declared premise closure.

### 4. Blind rediscovery benchmarks

Keep one independent success in each initial mathematical domain: arithmetic, algebra,
combinatorics, number theory, and geometry. The target theorem or equivalence class must be hidden
through the proof seal, actual pre-unseal reads must be constrained, and negative controls must
detect lookup, prefix-overfit, undeclared-premise, and unproved-generalization shortcuts.

This five-domain set is an alpha coverage floor. It is not the 200-slot curriculum completion
criterion and does not establish general theorem-discovery ability.

### 5. Durable execution and budgets

Exercise a bounded campaign through admission, checkpoint, resume, deadline, and terminal receipt
paths. Verify exact CPU/GPU ownership, work-unit accounting, LLM token and micro-dollar budgets, and
fail-closed recovery from a deliberately interrupted step. The rehearsal must not take ownership of
an unrelated runtime, process, database, lease, or GPU workload.

### 6. Computational accelerators

Run one exact CPU/GPU cross-check with a candidate-bound input and zero tolerated comparison
violations. Run one LLM-adapter rehearsal using an injected no-network provider or an explicitly
disabled readiness path, with no secret values, prompts, or raw responses persisted. Neither route
is proof or observational evidence.

### 7. Observational adapters

Run synthetic, authorized-schema packets through the Solar, galaxy, lensing, and cluster adapters.
These rehearsals test parsing, calibration roles, covariance handling, forbidden-field rejection,
split commitments, and rank-write protection. They must be labeled synthetic controls and must not
be reported as empirical support. Real-data admission remains blocked until an independently
authorized, hash-bound source packet is registered.

### 8. Human-readable research record

For one success, one rejection, and one missing-evidence block, generate both notebook and blog-style
records from immutable receipts. Each record must show:

1. the question and declared search space;
2. the candidate-generation path;
3. the exact derivation or counterexample;
4. the checks that passed and failed;
5. what the result proves;
6. what it explicitly does not prove;
7. the next missing premise or experiment;
8. receipt and source identities needed for replay.

## Alpha exit gate

The comprehensive alpha is reached only when all eight vertical slices have replayable receipts,
their focused tests pass in a clean checkout, and CI has no unresolved failure. The release summary
must publish a coverage matrix and list every blocked scientific claim.

The following remain post-alpha refinement work:

- filling the remaining blind curriculum slots;
- exhaustive full-D2F and high-atom reconciliation;
- global H7 estimates, tube preservation, and quantitative lifespan;
- full direction-sphere determination;
- broad interacting, curved, and nonminimal mathematical classifications;
- admission and analysis of real observational datasets.

This sequencing lets the product become broadly usable without weakening the evidentiary standard
that makes its successes and failures credible.
